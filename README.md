# mixuse — сравнение сочетаний функций на территории

Программа для метода НИР «смешанное использование территорий». Территория меняет назначение;
программа показывает, как каждый вариант сочетания функций (Ж, К, ОД, П) скажется на окружающих
кварталах. **Сводного балла и «лучшего варианта» нет** — выбор делает человек.

## Установка

Нужен Python 3.10+ и пакеты numpy, pandas, matplotlib, pyyaml, pytest:

```
pip install -r requirements.txt
```

Геометрия написана на numpy, без geopandas и shapely — ставить ГИС-библиотеки не нужно.

## Как посчитать свои данные

1. Положите слои в одну папку (GeoJSON или GeoPackage):
   - **кварталы** — полигоны (номер квартала — по желанию);
   - **здания** — полигоны с полями: жилое (1/0), этажность, площадь застройки, жилая площадь, жители
     (последние три могут отсутствовать — программа оценит их и напишет об этом в отчёте);
   - **сервисы** — папка «один файл = один тип сервиса» (тип — имя файла: `cafe.geojson`, `school.geojson`…);
     у школ и садов — поле `capacity` (число мест);
   - **зоны** — полигоны с кодом зоны (желательно).

   Слои могут быть в разных системах координат: градусы (EPSG:4326) и зоны UTM программа приводит
   к системе кварталов сама. EPSG:3857 не принимается — в нём искажены площади и расстояния.

2. Составьте файл настроек — программа сделает черновик сама:
   ```
   python -m mixuse init путь/к/папке --name mycity
   ```
   Откройте `configs/mycity.yaml` и проверьте строки с пометкой «ПРОВЕРЬТЕ»: какие поля что значат,
   какие коды зон относятся к П и ОД (`zone_rules`).

3. Проверьте данные:
   ```
   python -m mixuse check configs/mycity.yaml
   ```
   Программа перечислит ошибки (расчёт невозможен) и предупреждения (что принято по умолчанию).

4. Посчитайте таблицу кварталов и найдите номера кварталов территории:
   ```
   python -m mixuse blocks configs/mycity.yaml
   ```
   Откройте `results/mycity_кварталы.geojson` в QGIS — номер квартала в поле `block_id`.

5. Сравните варианты:
   ```
   python -m mixuse compare configs/mycity.yaml --territory 12,13
   ```
   (или впишите `territory: [12, 13]` в настройки).

## Устройство

```
mixuse/
  geometry.py     чтение слоёв, проекция, площадь, точка в полигоне, расстояния (из ноутбука без изменений)
                  + пересчёт градусы ↔ UTM
  groups.py       таблица групп сервисов, группа нежилого здания
  blocks.py       шаги 1–4: таблица кварталов (режимы «слои» и «таблица»), встроенные помещения
  compare.py      шаги 5–6: окружение и показатели
  scenarios.py    варианты
  checks.py       проверка данных; шаги 7 и 7б
  export.py       CSV, GeoJSON для QGIS, JSON для страницы, карта
  config.py       файл настроек YAML
  init_config.py  черновик настроек по папке с данными
  notebook.py     анкета ноутбука → настройки пакета; печать проверки данных
  cli.py          командная строка
  params.py       параметры по умолчанию — в одном месте
configs/          spb.yaml, gatchina.yaml, vysotsk.yaml — примеры (повторяют примеры ноутбука)
examples/         данные примеров из архива v4 (не входят в репозиторий)
tests/            тесты; tests/etalon — эталоны ноутбука v4 (results/ архива)
таблица_групп_сервисов.csv     тип сервиса → группа, 108 строк (своя таблица — service_groups: в настройках)
метод_сравнения_вариантов.ipynb  рабочий ноутбук: анкета и шаги 0–9, расчёт — функциями пакета
пример_расчёта_ВО.ipynb, листинг_метода.py, конструктор_смешанности.html,
README.txt        материалы ноутбука v4 (16.11.2026) — без изменений
```

Тесты: `python -m pytest tests`.

## История изменений

### 0.3.0 — 19.11.2026. Ноутбук вызывает пакет (этап 2)

Расчёт не изменился: результаты ноутбука для spb, gatchina и vysotsk совпадают с эталонами v4
(`tests/test_notebook.py` выполняет ячейки ноутбука и сверяет все файлы `results/`).

- `метод_сравнения_вариантов.ipynb` больше не содержит своих функций: ячейки шагов 0б–9 вызывают
  пакет `mixuse`. Анкета шага 0, примеры, параметры `P` и варианты `SCN` остались на месте.
  Папка `mixuse/` должна лежать рядом с ноутбуком.
- Пути примеров в ноутбуке — `examples/…` (как в репозитории), а не `data/…`.
- Проверка данных в ноутбуке (шаг 0б) — та же, что в команде `check`: текст сообщений другой,
  чем в ноутбуке v4, условия остановки прежние (ошибка — расчёт не идёт).
- Новое в пакете: `mixuse/notebook.py` — перевод анкеты в настройки и печать проверки;
  `export.map_figure` — карта для показа в ноутбуке (`map_png` сохраняет её в файл, как раньше).

### 0.2.0 — 17.11.2026. Пакет приведён к ноутбуку v4

Эталон — `results/` архива `метод_сравнения_вариантов_v4.zip`. Все таблицы spb, gatchina и vysotsk
(таблица кварталов, сравнение, устойчивость, встроенные, JSON для страницы) совпадают с эталоном;
в Гатчине 2 площади в таблице и 1 в JSON отличаются на 1 в последнем знаке (граница округления).
Контрольные числа ТЗ, раздел 8, сходятся, в том числе со встроенными помещениями.

Что изменилось в расчёте по сравнению с 0.1.0 (всё — как в ноутбуке v4):
- **Таблица групп на 108 типов** (`таблица_групп_сервисов.csv`, разделитель «;»). Тип ищется по столбцу
  «тип», затем по тегам OSM. Группы: К, ОД, П, школа, детский_сад, метро, остановка, нет. Часть типов
  сменила группу (например, `multifunctional_center` и `guest_house` → «нет»), поэтому встроенная площадь ОД
  на Васильевском острове стала 7 300 м² вместо 8 367, а домов со встроенными помещениями — 345 вместо 350.
- **У нежилых зданий жителей и жилой площади нет**, даже если в поле что-то записано. На Васильевском
  острове это убрало 189 жителей (208 713 → 208 524).
- Если поля жителей нет, жители = жилая площадь ÷ q, где жилая площадь уже уменьшена на встроенные помещения.
- Признак «жилое» читается как в ноутбуке: жилыми считаются 1, True, да, yes.
- **Блок «Работа и жильё»**: убраны «Отклонение от среднего |K−K_ref|», порядок вариантов, строка «Сигналы»
  и параметры `kit_max`, `r_szz`. Добавлены «Изменение рабочих мест к нынешним», «Работа на жителя K:
  окружение», «Работа на жителя K: все данные». Школы и сады: ученики с территории, обеспеченность, %,
  не хватает мест.
- Шаг 7 показывает K окружения «как есть» и изменение K в вариантах; шаг 7б — новый формат таблицы.
- JSON для страницы — формат ноутбука v4 (`format_version: 1`, параметры, варианты, территория).
- Сервисы: можно указать поле числа мест (`capacity_field`) и поле типа, в том числе список полей OSM.
- Высоцк: данные `data/vysotsk/` архива v4 (кварталы в EPSG:4326, номер = порядок в файле),
  две папки сервисов (сервисы, промышленность), территория 362, 387, 392 — пример.

Отличие пакета от ноутбука (не влияет на эталоны): слои в разных системах координат (градусы и UTM)
пакет приводит к системе кварталов, а ноутбук останавливается с ошибкой.

### 0.1.0 — 17.11.2026. Перенос ноутбука в пакет (этап 1)

- Расчёт шагов 1–9 перенесён из `листинг_метода.py` (ноутбук от 29.10.2026) без изменений формул.
  При `builtin: нет` таблицы кварталов, сравнения и устойчивости совпадают с эталонами `results/`
  для spb и gatchina (тесты `tests/test_etalon.py`).
- **Новое в расчёте: встроенные помещения** (по ТЗ, п. 4.3.4), переключатель `builtin`, по умолчанию «да».
  В жилом доме не ниже 2 этажей с n сервисами К и ОД внутри: B = min(n · 100, 0,5 · S),
  B делится между К и ОД по числу сервисов. Как видно в результатах: растут `nr_К`, `nr_ОД`, рабочие
  места и K; новые столбцы `встр_К`, `встр_ОД`. Числа ТЗ (345 домов, 56 390 / 7 300 м²) пока
  **не воспроизводятся** (у нас 350 / 56 325 / 8 367) — нужна новая версия ноутбука автора.
- **Новое в подготовке данных: слои в разных системах координат** приводятся к системе кварталов
  (градусы ↔ UTM). В ноутбуке такие слои молча не совпадали бы. На числа spb и gatchina не влияет
  (у них все слои в одной системе).
- Отчёт о подготовке дополнен счётчиками: здания без этажности, без числа жителей, школы и сады без
  числа мест, нежилые здания меньше S_min, как определена группа нежилых зданий.
- Справочник групп сервисов вынесен в CSV (43 типа — как в ноутбуке). Коды ВРИ не заполнены —
  [НУЖЕН ИСТОЧНИК]: таблица на 108 типов у автора.
