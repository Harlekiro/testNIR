# mixuse — сравнение сочетаний функций на территории

Программа для метода НИР «смешанное использование территорий». Территория меняет назначение;
программа показывает, как каждый вариант сочетания функций (Ж, К, ОД, П) скажется на окружающих
кварталах. **Сводного балла и «лучшего варианта» нет** — выбор делает человек.

## Установка

Нужен Python 3.10+ и пакеты numpy, pandas, matplotlib, pyyaml, pytest:

```
pip install -r requirements.txt
```

Геометрия написана на numpy, без geopandas и shapely — ставить ГИС-библиотеки не нужно.

## Как посчитать свои данные

1. Положите слои в одну папку (GeoJSON или GeoPackage):
   - **кварталы** — полигоны (номер квартала — по желанию);
   - **здания** — полигоны с полями: жилое (1/0), этажность, площадь застройки, жилая площадь, жители
     (последние три могут отсутствовать — программа оценит их и напишет об этом в отчёте);
   - **сервисы** — папка «один файл = один тип сервиса» (тип — имя файла: `cafe.geojson`, `school.geojson`…);
     у школ и садов — поле `capacity` (число мест);
   - **зоны** — полигоны с кодом зоны (желательно).

   Все слои набора — в одной системе координат: EPSG:4326 (градусы) или метрической (UTM, МСК).
   Смешение систем — ошибка проверки (правило 4.1.2); только в режиме совместимости `rules: v4`
   программа приводит градусы и зоны UTM к системе кварталов сама. EPSG:3857 не принимается —
   в нём искажены площади и расстояния.

2. Составьте файл настроек — программа сделает черновик сама:
   ```
   python -m mixuse init путь/к/папке --name mycity
   ```
   Откройте `configs/mycity.yaml` и проверьте строки с пометкой «ПРОВЕРЬТЕ»: какие поля что значат,
   какие коды зон относятся к П и ОД (`zone_rules`).

3. Проверьте данные:
   ```
   python -m mixuse check configs/mycity.yaml
   ```
   Программа перечислит ошибки (расчёт невозможен) и предупреждения (что принято по умолчанию),
   а затем составит **отчёт о данных** (`results/<код>_отчёт_о_данных.txt`): здания без этажности —
   жилые и нежилые отдельно, жилые дома без числа жителей, школы и сады без числа мест, точки
   предприятий в контурах зданий, производственные кварталы без точек предприятий — и подскажет,
   что дополнить в данных.

4. Посчитайте таблицу кварталов и найдите номера кварталов территории:
   ```
   python -m mixuse blocks configs/mycity.yaml
   ```
   Откройте `results/mycity_кварталы.geojson` в QGIS — номер квартала в поле `block_id`.

5. Сравните варианты (а для перебора всех сочетаний долей — `python -m mixuse explore configs/mycity.yaml`):
   ```
   python -m mixuse compare configs/mycity.yaml --territory 12,13
   ```
   (или впишите `territory: [12, 13]` в настройки).

## Устройство

```
mixuse/
  geometry.py     чтение слоёв, проекция, площадь, точка в полигоне, расстояния (из ноутбука без изменений)
                  + пересчёт градусы ↔ UTM
  groups.py       таблица групп сервисов, группа нежилого здания
  blocks.py       шаги 1–4: таблица кварталов (режимы «слои» и «таблица»), встроенные помещения
  compare.py      шаги 5–6: окружение и показатели
  scenarios.py    варианты
  checks.py       проверка данных; шаги 7 и 7б
  export.py       CSV, GeoJSON для QGIS, JSON для страницы, карта
  config.py       файл настроек YAML
  init_config.py  черновик настроек по папке с данными
  notebook.py     анкета ноутбука → настройки пакета; печать проверки данных
  data_report.py  отчёт о данных (этап 3): только счётчики, без формул
  buildings.py    правила v5 для зданий: шаги 1–8 таблицы 4.4 (категории А / Б / В), встроенные помещения по норме типа
  cli.py          командная строка
  params.py       параметры по умолчанию — в одном месте
configs/          spb_full.yaml, gatchina_layers.yaml, vysotsk.yaml — наборы для правил v5;
  legacy/         spb.yaml, gatchina.yaml, vysotsk.yaml — режим совместимости v4 (примеры ноутбука v4)
data/             gatchina_layers/ — Гатчина послойно; spb_full/ — весь Петербург (не входит в репозиторий)
examples/         данные примеров из архива v4 (не входят в репозиторий)
tests/            тесты; tests/etalon — эталоны ноутбука v4 (results/ архива)
таблица_групп_сервисов.csv     тип сервиса → группа, 108 строк (своя таблица — service_groups: в настройках)
метод_сравнения_вариантов.ipynb  рабочий ноутбук: анкета и шаги 0–9, расчёт — функциями пакета
пример_расчёта_ВО.ipynb, листинг_метода.py, конструктор_смешанности.html,
README.txt        материалы ноутбука v4 (16.11.2026) — без изменений
```

Тесты: `python -m pytest tests`.

## История изменений

### 0.8.0 — 19.11.2026. Обеспеченность школами и садами через blocksnet (этапы 8.3–8.5)

Модуль `mixuse/provision_bn.py` — единственный, который импортирует blocksnet; ядро без него работает как раньше.
blocksnet 1.0.0.dev1 закреплён в `pyproject.toml` (группа `[blocksnet]`); ставится в отдельное окружение с Python 3.11:
`py -3.11 -m venv …`, `pip install -e .[blocksnet]`. Решения автора (19.11.2026): граф пешеходный; нормы и пороги —
из настроек blocksnet (школа 120 мест на 1 000 жителей, 15 мин; сад 61, 7 мин); `max_depth = 2`; учреждениям без
числа мест — наименьшая вместимость каталога blocksnet (250 и 80).

- **8.3. Матрица доступности** — `python -m mixuse access configs/<код>.yaml` → `data/<код>/access/matrix_walk.pickle`
  и описание `.json` (версия blocksnet, граф, число кварталов, контрольная сумма слоя кварталов). Матрица строится
  по кварталам mixuse: индекс — block_id, тот же порядок; при загрузке соответствие проверяется.
  Граф скачивается из OpenStreetMap частями (~7 × 7 км) с сохранением каждой части; `--retries 0` — пробовать,
  пока сервер не ответит (серверы Overpass по очереди). Высоцк — 473 × 473 (граф 2 мин), Гатчина — 517 × 517 (3 мин).
  Петербург: публичный сервер Overpass перегружен, граф скачивается.
- **8.4. Обеспеченность «как есть»** — `python -m mixuse provision configs/<код>.yaml` →
  `results/<код>_обеспеченность.csv` (весь набор и окружение: в пределах доступности и «получили место вообще»;
  запасной расчёт 4.7.3 рядом; проверка 12.8; порог × 0,5 / 1 / 1,5) и `_обеспеченность_кварталы.csv`.
- **8.5. Варианты** (12.4, 12.5): если blocksnet установлен и матрица есть, `compare` заменяет строки школ и садов
  на строки 12.5 — обеспеченность окружения в пределах доступности, дети с территории, из них обеспечены, изменение
  обеспеченности окружения (п. п.), получили место вообще; в выводе дети без места = дети − из них обеспечены.
  Иначе — запасной расчёт 4.7.3 с предупреждением. `--near 3` — расчёт по кварталам не дальше 3 порогов от территории
  (12.4): на Высоцке и Гатчине совпадает с полным расчётом (разница 0,00 п. п.; тест — не больше 0,5).

### 0.7.0 — 19.11.2026. Перебор сочетаний (этап 6)

Команда `python -m mixuse explore configs/<код>.yaml` (ТЗ, раздел 7; только правила v5):
- все сочетания долей допустимых групп с шагом, дающие 100 %; по умолчанию Ж, К, ОД, шаг 10 %, К не больше 20 %
  (30 сочетаний). Ключи: `--groups Ж,К,ОД,П`, `--step 5`, `--max К=20`, `--min ОД=10`, `--territory`,
  `--filter "K окружения>=0.5"` (можно несколько). То же — разделом `explore:` в файле настроек
  (`groups`, `step`, `max`, `min`, `filters`);
- для каждого сочетания — показатели 4.7 той же функцией, что для вариантов (N, J, ΔJ, K окружения и нижняя граница,
  K по всем данным, доступ к К и ОД, жители рядом с производством, школьники и дошкольники без свободного места);
- `results/<код>_перебор.csv` — «сочетание × показатели»; порядок — по долям, **без сортировки по показателям**;
  первая строка — «Как есть»; фильтр оставляет порядок;
- `results/<код>_перебор_сводка.csv` — диапазон каждого показателя и влияние долей: коэффициент корреляции r с долей
  каждой группы, изменение показателя при доле больше на 10 п. п. и группа с наибольшим |r|. Рекомендаций нет.
- В ноутбуке — шаг 10 «Перебор сочетаний».

### 0.5.0 — 19.11.2026. Правила v5 (этап 4)

При `rules: v5` (настройки `spb_full`, `gatchina_layers`, `vysotsk`) рабочие места в существующей застройке

- **Нормы по типам сервисов** (4.4.3, раздел 6): норма здания — по типу, точек которого в здании больше;
  при равенстве — большая норма; тип без нормы — норма группы для вариантов (28 / 15 / 69) со счётчиком.
- **Встроенные помещения** (4.3) — рабочие места по норме типа сервисов этой группы в доме; относятся к категории А.
- **Категории зданий** (4.4, шаги 1–8): сервис К/ОД/П → норма типа; социальный объект (список `social_norms`):
  школа — мест ÷ 13,5, без мест — 0; несколько социальных типов — правило 4.4.3; производственная зона —
  круглый контур без сервиса (4πS/P² ≥ 0,88, вершин ≥ 10) — сооружение, 0; от 2 этажей — A ÷ 69; одноэтажное
  от 1 000 м² — A ÷ 81; меньше — 0; общественно-деловая зона — A ÷ 50; прочее — 0.
- **Две оценки** (4.4.5): основная (А + Б) и нижняя граница (только А).
- **Наличие функций** (4.5): К и ОД — только по сервису или встроенному помещению; П — по сервису или зданию шагов 4–5.
